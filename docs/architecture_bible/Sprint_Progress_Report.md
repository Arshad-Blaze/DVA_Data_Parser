# Architecture Rectification Sprint — Progress Report

## 1. Objective

Execute the **Architecture Rectification Sprint** from PROMPT.md: convert the DVA Platform from a workflow-driven app into a **pipeline-driven data processing platform** with strict layer separation:

```
UI → Workflow Engine → Pipeline Registry → Pipeline Context → stages
```

The sprint is scored on layer boundaries (verified by docs/tests), not features.

## 3. Stream A — Layer-boundary fixes (H2/H5/H6, all resolved)

### H2 — UI bypassed the workflow facade into the ParserFactory
- **Problem:** `ui/helpers.py::autoparse_context` constructed and ran the parser directly (`default_factory.create(discovery).parse(...)`), performing backend work in the UI.
- **Fix:** new `dav_tool/workflow/parsing.py` exposes `parse_from_discovery(discovery, file_paths, ...)`; `autoparse_context` now calls this service.
- **Why:** restores Parser layer as a service behind the Workflow facade; UI stays presentation-only.

### H5 — Validation layer invoked Report generation
- **Problem:** `workflow/validation.py` imported/called `_reports.generate_file_review` — a Validation→Reporting boundary crossing.
- **Fix:** removed that call; file review is now generated by the coordinator `workflow/orchestration.py::_generate_file_review`, which calls the Reporting layer with precomputed summaries.
- **Why:** Validation now owns only business rules; Reporting is invoked by the workflow layer, matching the prescribed architecture.

### H6 — Reports layer re-aggregated as a fallback
- **Problem:** `_reports.generate_file_review` could stream/re-aggregate data itself when summaries were missing — Reports doing Aggregation work and re-reading files.
- **Fix:** `generate_file_review` now **requires** precomputed store/UPC summaries (raises `ValueError` if absent); fallback loops and `stream_store_aggregate`/`stream_upc_summary` removed.
- **Why:** guarantees single aggregation pass; enforces the Aggregator→Reports data flow for 500 MB+ files.

### Bonus real bugs found & fixed via new tests
- `WorkflowEngine.select_pipeline` crashed on an unregistered requested pipeline → now falls back with error.
- `reporting._build_artifacts/_build_kpis/_build_sheets` used dangerous `or`/truthiness on DataFrames → replaced with `is None` checks (polars DataFrames are falsy when empty).

The final mandated sprint item. Approach chosen deliberately: **wire the platform in without rewriting the two ~1,000-line certified UI pages.**

| File | Change | Why |

## 5. How it all connects

```
startup          dav_tool/ui/app.py  →  ensure_bootstrap()
                                           │
                                           ▼
dav_tool/ui/platform.py  ←  ServiceRegistry (pipeline/bootstrap.py)
   │                            ├ config, observability
   │                            ├ parser_registry + parser_factory
   │                            ├ pipeline_registry (5 pipelines)
   │                            ├ rule_registry (9 rules)
   │                            └ workflow_engine (WorkflowEngine)
   │
   ├─ pages read engine/registries via ui/platform.py  (presentation-only)
   ├─ parsing flows through workflow/parsing.py → ParserFactory   (H2)
   ├─ file review flows through workflow/orchestration._generate_file_review → _reports (H5/H6)
   └─ phase ints on ctx == WorkflowPhase values (onboarding)
```

Each prior fix is a dependency for the wiring:
- **H2** guarantees the UI's parser path already crosses the Workflow facade, so the UI never needs direct parser access later.
- **H5/H6** guarantee the Aggregator→Validation→Reports data hand-off is single-pass, so the engine's PipelineContext can feed reporting without re-aggregation.
- **Phase alignment** guarantees `WorkflowState` can take over rendering without a visual change.

## 6. C1 — Status & Connection

**C1 (Critical):** *"UI is the workflow state machine."* `ctx.phase` ints are mutated directly across ~2,000+ lines of UI, while the declared `WorkflowState` class (`workflow/__init__.py:63`) is never instantiated.

**Progress to date:**
- Onboarding's phase ints now **equal** `WorkflowPhase` values (DISCOVERY=1 … REPORTS=6), so `WorkflowState` can drive onboarding *as-is*.
- The engine + registry are now reachable from the UI via `ui/platform.py`.
- Docs updated to state exactly what remains.

**Remaining (deliberately not done):**
1. Replace onboarding's `ctx.phase = PHASE_*` mutations with `WorkflowState.goto()/advance()` (safe — values already match).
2. Map existing.py's **9-phase** scheme onto the **7** `WorkflowPhase` values before migrating (this is the risky part: 9 phases incl. `DISCOVERY_COMPARE`/`SCHEMA_COMPARE`/`MIGRATION_REPORT` have no 1:1 `WorkflowPhase`).

**Why work stopped at this point:** rewriting two ~1,000-line certified pages to drive a PipelineContext is the single highest-risk change in the sprint. The safe path is: bootstrap + accessor + phase alignment (done, 348 tests green), then a dedicated C1 pass for the state-machine migration, then the existing-flow phase mapping, then full pipeline-driving.
